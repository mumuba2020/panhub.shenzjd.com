# 网盘实时转存（转存劫持）方案

> 状态：调研完成，待决策是否实施。参考竞品：panlay.com（2026-08-20 验证在跑）
> 文档定位：上线实施时的技术方案与风险备忘

## 1. 背景与模式

**目标**：搜索结果中，用户点击「获取资源」时，后端把别人分享的链接资源**实时转存到自己网盘账号**（已绑定推广权限），再返回**自己账号生成的推广链接**，从而让转存/开会员收益归因到自己。

**竞品验证**：panlay.com 已跑通——用户点「获取资源」→ 显示「创建任务/转存资源中」→ 返回新链接（链接 5 分钟后失效防滥用）。

**归因机制核心**：网盘推广收益归「**链接生成者**」而非「资源所有者」。别人生成的分享链接，点击/转存收益归别人；只有用**自己绑定推广权限的账号**生成的链接，收益才归自己。

## 2. 开源方案选型（2026-08-20 调研）

| 项目 | 形态 | 网盘支持 | 集成方式 | 许可证 | 匹配度 |
|---|---|---|---|---|---|
| **yilane/QuarkPanTool** | 独立 REST API 服务（Python+Firefox，Docker） | 夸克 | PanHub 后端 HTTP 调 `/api/v1/share/transfer-and-share`，返回新链接 | 开源 | ⭐⭐⭐⭐⭐ 最现成 |
| **wgx0307/netdisk** | Go SDK，核心 `netdisk.Transfer(shareURL)` | 夸克/百度/阿里/UC/迅雷 | Nuxt 后端自集成或包装微服务 | 开源 | ⭐⭐⭐⭐⭐ 覆盖面最广 |
| **Cp0204/quark-auto-save** | 定时批处理 + WebUI（Docker:5005） | 夸克 | 定时任务模式，**非用户点击实时触发** | AGPL-3.0 ⚠️传染性 | ⭐⭐⭐ 不是实时，不适用 |
| **ctwj/urldb** | 完整「搜索+转存+资源库」平台（Go+Nuxt+PG） | 8 网盘（夸克已支持转存） | 太重 | GPL ⚠️不可直接复用 | ⭐⭐⭐⭐ 可参考架构 |

**结论**：优先 **A. 独立部署 yilane/QuarkPanTool**（最快落地，PanHub 只做 HTTP 调用）；备选 **B. 用 wgx0307/netdisk 思路自实现**（免多一个服务，但需从零写，维护成本高）。

## 3. 推荐架构（与广告位协同）

```
PanHub 后端 ──► yilane/QuarkPanTool (Docker :8007) ──► 夸克官方 API（Cookie）
   │                    └─ 转存 + 生成新分享链接
   ├─ 合规资源 → 显示「获取资源」按钮 → 转存链路
   └─ 影视/敏感资源 → 保留「访问」按钮 → 跳原链接（不碰）
```

**红线**：转存只对**合规资源**（软件/工具/学习资料/AI 素材等）开启；影视类等版权敏感资源一律不转存，避免实名推广账号批量转存盗版被清退。

## 4. 风险清单（实施前必读）

| 风险 | 说明 | 缓解 |
|---|---|---|
| 封号 | 夸克/百度风控严格，高频转存特征明显 → 推广权限+账号双失 | 限频、低并发、单账号配额、监控告警 |
| 版权 | 批量转存盗版影视 = 实名账号背书，风险远超单纯搜索 | 只转存合规资源（见第 3 节红线） |
| 维护 | 平台 API/风控一变即挂，Cookie 需续期 | 保留现成项目跟进上游；Cookie 过期告警 |
| 体验 | 实时转存 2-30s，失败率高（失效/需密码/超大文件） | 前端显示任务进度；失败自动回退「访问」按钮 |
| 协议 | AGPL/GPL 项目不可直接进 PanHub 代码库 | 用 yilane（独立进程隔离）或自实现 |

## 5. 实施步骤

- **P0（决策）**：确认主线（会员 CPS 直链）上线并观察数据后，再决定是否上转存辅线
- **P1（如果做）**：
  1. 独立部署 yilane/QuarkPanTool（Docker，配置夸克 Cookie）
  2. PanHub 后端加 `/api/transfer` 代理（限流 + 只允许合规资源 + 记录日志）
  3. 搜索结果渲染：合规资源出「获取资源」按钮，走转存；其余保持「访问」
  4. 前端转存进度 UI（创建任务 → 转存中 → 返回新链接）
- **P2**：多网盘扩展（百度/阿里，参考 wgx0307/netdisk）；链接有效期策略（如 panlay 的 5 分钟失效，防资源被二次分发）
